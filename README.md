# 火羽直播实时字幕

在哔哩哔哩直播间看火羽（[live.bilibili.com/22748536](https://live.bilibili.com/22748536)）时，把直播服务器上的
日语→中文实时翻译字幕**叠在画面上**，像原生字幕一样看。

插件会自己从两台字幕服务器里挑当前状态好的那台，掉线自动换、断流自动重连。

---

## 安装

1. 打开 `chrome://extensions`（Edge 是 `edge://extensions`）
2. 右上角打开「开发者模式」
3. 点「加载已解压的扩展程序」，选择本目录（含 `manifest.json` 的那一层）
4. 打开火羽直播间，字幕会自动出现

> 需要 Chrome / Edge 109 以上（用到 offscreen 文档）。

## 用法

点扩展图标可以：

- **总开关**：临时关掉字幕
- **字幕服务器**：默认「自动选择」，也可以手动锁死某条线；卡片上会显示延迟、在线人数、失败原因
- **显示效果**：字号、最多行数、底部距离、是否显示日语原文
- **字幕延迟**：见下面「为什么字幕和画面不同步」

## 为什么字幕和画面会错位

这是这类工具最容易踩的坑：**字幕是实时的，画面却有缓冲**。

主播说话 → 服务器转写翻译（约 1~3 秒）→ 推给你；而你的直播画面比主播实际动作晚
2~10 秒（取决于你的网络和 B 站缓冲）。两边一叠加，字幕就会「跑到画面前面」。

所以插件里有个**字幕延迟**滑块（0~30 秒）：把它调到字幕刚好跟上画面的那个点。
经验值：普通清晰度先试 6~8 秒，低延迟模式试 3~5 秒。

## 它是怎么工作的

两台服务器（`123.60.104.22:6006`、`106.15.35.175:6006`）跑的是同一套字幕服务，
对外提供两个接口：

| 接口 | 用途 |
|---|---|
| `GET /healthz` | 健康检查：是否在转写、音频是否连着、在线人数、带宽配额 |
| `GET /events?k=hy` | SSE 长连接，实时推送字幕和弹幕 |

`/events` 的事件大致是：

```jsonc
{ "type": "snapshot", "lines": [...], "dms": [...], "room": {...}, "live": {...} }
{ "type": "line",     "line": { "id": 1201, "zh": "中文译文", "ja": "日语原文", "t": "20:31:07", "ts": 1792218... } }
{ "type": "line_upd", "id": 1201, "zh": "补上的译文" }   // 先出原文，译文稍后回填
{ "type": "status",   "viewers": 8, "connected": true }
{ "type": "move",     "url": "http://..." }              // 服务器要求换线路
{ "type": "reset" }                                       // 切换了直播间
```

几个关键设计：

**1. 为什么不用 content script 直连**

B 站是 `https`，字幕服务器是 `http`。https 页面里请求 http 资源会被浏览器的混合内容策略直接拦掉。
所以真正建立连接的是扩展的 **offscreen 文档**（特权上下文，不受此限制），再通过 background
把事件转发给页面。

```
offscreen (EventSource) ──► background (选路/去重/缓存) ──► content script (渲染)
```

**2. 状态良好怎么判断**

每次探测对 `/healthz` 打分：`ok`、`connected`、`msg` 里是否含「未开播 / 重连失败」、
带宽配额是否告警、以及响应延迟。分数最高者胜出。

另外两台其实是接力关系——线路一的 `msg` 写着「字幕来自 106.15.35.175」，
所以线路一更像中转节点。谁快用谁，数据是一样的。

**3. 遇到限流怎么办**

服务器对人数有上限，超了返回 429。插件会按 1.5s → 3s → 6s → 12s → 25s → 45s
的阶梯退避重试，绝不会把服务器打爆，也不会疯狂重连。

**4. 字幕完整性**

`line` 事件先带日语原文和（可能为空的）译文，译文随后通过 `line_upd` 回填。
插件按 `id` 去重合并，所以不会出现重复行，译文补上时原地替换、不闪。

## 目录结构

```
manifest.json     扩展清单（MV3）
background.js     选路、健康探测、SSE 事件分发、配置持久化
offscreen.js      真正持有 EventSource 长连接的地方
content.js        字幕渲染层（Shadow DOM，跟随播放器位置和全屏）
popup.html/js     控制面板
docs/preview.html 纯前端的字幕效果预览页（可连真实服务器）
tests/            本地回归测试（mock 直播间 + 静态服务器）
icons/            图标
```

## 本地自测

不装扩展也能验证渲染层：

```bash
node tests/serve.mjs
# 浏览器打开 http://127.0.0.1:8899/22748536
```

这个页面用一个 canvas 生成的 `MediaStream` 冒充直播画面，打桩 `chrome.runtime` 后直接加载
`content.js`，并模拟推送三条字幕。字幕能正确压在弹幕上方、贴在播放器底部，就说明定位与
渲染逻辑没坏。

## 常见问题

**字幕一直没出现？**
先看 popup 里是不是「未开播」。主播没开播时服务器不会产生字幕。开播后一般 3 秒内就会出来。

**显示「连接异常」或「人数已满」？**
服务器限流了，等它自动重连即可（最长 45 秒一次）。也可以手动到 popup 里切另一条线路。

**全屏后字幕不见了？**
插件监听 `fullscreenchange`，会把字幕层搬进全屏元素内部。如果你用的是 B 站的
「网页全屏」而不是真全屏，字幕依然按播放器位置定位。若仍异常，退出全屏再进一次。

**改完设置要刷新页面吗？**
不用，改完立刻生效。只有扩展本身重新加载时才需要刷新直播页。

## 说明

非官方工具，与哔哩哔哩及主播无关。字幕内容由上述第三方服务器提供，本插件只负责取回并显示。
接口若变更，插件可能失效。请合理使用，勿高频重连。
